# Examples

Real output from real runs, committed so the pipeline's output is visible
without cloning the repo or supplying an API key. Nothing here is
hand-written or fabricated; every file below states the exact command
that produced it.

- **[`digest-san-jose-2026-06-09.md`](digest-san-jose-2026-06-09.md)** —
  a real digest generated by `digest/generate_digest.py` from the eight
  real, confidence-routed San José City Council agenda items used in
  M4's live review session (`scripts/run_review_demo_batch.py`). Checked
  against the real style checker (`checks/style_check.py`) after
  generation: 0 high-severity findings, 8 low/medium findings — the
  digest passed the gate, and the findings are left in as an honest look
  at the judge tier's known behavior (see
  [`docs/style-checking.md`](../docs/style-checking.md)). Generated
  2026-08-04 via `digest/generate_digest.py` called directly (the same
  code path `scripts/check_sample_digest.py` exercises).

- **[`eval-scorecard.txt`](eval-scorecard.txt)** — actual stdout from
  `uv run civic eval` against the real 44-case gold set, generated
  2026-08-04. Numbers differ slightly from the committed
  [`evals/baseline.json`](../evals/baseline.json) (e.g. locations F1
  0.696 here vs. 0.60 in the baseline) because a live model call isn't
  perfectly deterministic case to case — the harness's own regression
  check confirms this run is within tolerance of the baseline ("No
  regression vs. baseline"). The README's
  [Results at a glance](../README.md#results-at-a-glance) table cites
  the committed baseline, not this run, since the baseline is the
  reviewed, pinned number.

- **[`drift-report.md`](drift-report.md)** — the real health report
  `metrics/report.py` renders for the simulated connector-rot case
  documented in [`docs/metrics.md`](../docs/metrics.md): a real M4
  extraction run recorded as a baseline, compared against a deliberately
  broken run with `people` silently stripped. Generated by calling
  `metrics/drift.py` and `metrics/report.py` directly against the
  already-recorded `data/metrics/` history — no API key required, since
  drift detection never calls an LLM.

- **[`review-session.txt`](review-session.txt)** — a terminal transcript
  of `civic review` resolving the real 10 items queued by the June 9,
  2026 M4 live review run. The original session wasn't captured to a
  file at the time it happened (see the results table in
  [`docs/review.md`](../docs/review.md) instead), so this transcript was
  produced afterward by replaying the exact real accept/reject calls and
  reasons already committed under `data/review_queue/` against a
  temporary copy of those same files reset to `pending` — the CLI
  output, proposed values, confidences, and provenance spans shown are
  the genuine article; only the timing is reconstructed, not the
  content or the decisions.
